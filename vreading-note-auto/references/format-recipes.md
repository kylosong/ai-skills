# 排版方案与取舍记录

2026-10-05 实际迭代过程,记录**为什么最终是这个格式**,避免以后重复试错。

## 迭代过程

### v1 · 初始版
划线用 `> 引用块`,想法用 `**💭 我的想法**` + 缩进段落。

**问题**:想法里那句 `.replace('\n', ' ')` 把段落全换成空格,
45 条多段落划线糊成整块(涉及 20 章)。

### v2 · 想法与划线同格式
划线和想法都用 `> 引用`,渲染出来**完全一样**,分不清。

→ 想法改为无引用块的缩进段落。

### v3 · 加分隔符
想用 `---` 断开配对组与后续划线,**被印象笔记吞掉**(回读 `---` 和 `<hr>` 都是 0)。
换 `· · ·` 成功保留 100 处。

### v4 · 有序号 + 分隔符
划线改 `1. 2. 3.`,分隔符保持 `· · ·`。

用户反馈**视觉一般**——划线全是同一种引用样式,长短不分、零散、没有节奏。

### v5 · 三方案对比
生成 HTML 预览让用户挑:

| 方案 | 特点 |
|---|---|
| A 极简留白 | 短句加粗变重,长段落轻量,最接近原观感 |
| B 卡片分组 | 每条一张卡带序号,原文/想法双色分层,边界最清晰 |
| C 编号清单 | 圆点编号 + 短句高亮,视觉节奏最强 |

### v6 · 圆点分隔 + 圆点编号(用户选择)
分隔符保留 `· · ·`,划线改圆点编号。

**踩坑**:曾试图改成 `*`,实测**孤立星号被吞**(回读 0 个),白测一场。

### v7 · 微信读书原生格式 ⭐ 最终版
用户贴出微信读书导出截图,要求照它来:

- 章节标题去掉中点:`## 第 3 章明末女真人崛起`
- 划线用 `-`(圆点),不用 `1.`
- 想法**内联**在原文末尾括号里
- 去掉章节分布表
- 去掉「原文」小标题

### v8 · 修复段落丢失
用户发现多段落划线**没有圆点**。

**原因**:多段落走了缩进分支,首段没有 `- `,Markdown 不认作列表项。

→ 修正为首段 `- `、后续缩进。**这是最容易反复踩的坑**。

### v9 · 精简统计 + 对齐
- 统计文案精简掉冗余说明
- 「阅读时间」用 `> ` 空引用行隔断,与「笔记统计」左对齐

### v10 · 阅读轨迹分段
一整句拆成按日期的列表,并**修正事实错误**:原写「10-01~10-02」「四天读完」,
查真实数据发现 10-01 无笔记,实际只有 09-30 / 10-02 / 10-03 三天。

## 最终格式规范

````markdown
## 📖 阅读分析

**《书名》** — 作者

> **笔记统计** ｜ 全书 N 条 = 划线 X + 想法 Y（去重后正文 Z 条）
>
> **阅读时间** ｜ 起 → 止，实际有笔记的三天：MM-DD / MM-DD / MM-DD

**阅读轨迹**

- **MM-DD**｜N 条 · 章节名、章节名等

**两条清晰的主线**

- **主线名** —— 说明

**几个锚点**

- 观察点

## 第 N 章 章节名

- 单段落划线

- 多段落首段
  后续段
  第三段

- 划线原文（💭 **我的想法**：想法内容）
````

---

## 为什么最终选这个格式

| 决策 | 原因 |
|---|---|
| 微信读书原生风格 | 用户本来就在用微信读书导出,格式熟悉,零学习成本 |
| 圆点而非数字编号 | 数字编号强调"第几条",圆点只做视觉分层,不抢内容 |
| 想法内联 | 原文和想法是同一件事,拆开反而割裂 |
| 不加「原文」标题 | 冗余,一眼就能看出哪条有想法 |
| 不加分隔符 | 圆点符号本身已提供视觉节奏,再加就是噪音 |
| 不加章节分布表 | 笔记开头已有阅读轨迹,重复了 |

## 重建方法

若要调整格式,改 `scripts/build_note.py` 的 `build()` 函数,重点看渲染循环:

```python
for ts, kind, txt, extra in items:
    if kind == 'mark':
        paras = _split(txt)
        if len(paras) > 1:
            L.append('- %s' % paras[0])   # 首段必须有 - 
            for p in paras[1:]:
                L.append('  %s' % p)      # 后续缩进
        else:
            L.append('- %s' % txt)
```

改动后**务必先建临时笔记验证**(标题加「【临时】」),因为:
- 印象笔记 API 不支持删除笔记
- 某些 Markdown 语法会被吞,只有实际写入才知道结果
